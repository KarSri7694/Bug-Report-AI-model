Pipeline Explaination

How Data Flows Through src/model.py

This single page maps the complete pipeline in src/model.py: CLI parsing, CSV ingestion, schema adaptation, feature materialization, binary label derivation, balancing, tensorization, ADLM style BiLSTM + CRF training, metric computation, and checkpoint export.

Primary Input

Raw issue CSVs or already prepared 4-feature CSVs from one or multiple files.

Feature Branches

Text tokens, temporal vector (2), categorical vector (29), contextual vector (3).

Label Space

Binary report labels: non_duplicate = 0, duplicate = 1.

Main Outputs

Prepared balanced CSV plus a .pt checkpoint containing model state, config, vocab, and metrics.

Detailed Stage Breakdown

These cards explain exactly what enters, what transformation runs, and what leaves each major stage.

Stage A: Ingestion and Schema Standardization

load_modeling_dataframe

Input

Any CSV with either the canonical 4 feature columns or raw issue-style columns.

Transform

  • Column names are trimmed.
  • If the 4 model columns are missing, the script checks if source fields are sufficient.
  • When sufficient, it converts source columns into standardized feature payloads.

Output

DataFrame with textual_features, categorical_features, temporal_features, and contextual_features.

Stage B: Feature Materialization

build_*_vector helpers

Input

Text and JSON-like strings in feature columns.

Transform

  • Text is normalized with tokenization and stopword filtering.
  • Temporal values are parsed to days since epoch and hours from LUCENE-1.
  • Categorical vector becomes one-hot over priority, severity, type, component.
  • Context vector becomes numeric IDs (or presence fallback values).

Output

Per-row numeric arrays: temporal length 2, categorical length 29, contextual length 3.

Stage C: Binary Label Derivation and Balancing

prepare_training_dataframe

Input

Materialized rows from one or more datasets.

Transform

  • Detect supervision column from explicit option or known candidates.
  • Map labels to non_duplicate or duplicate.
  • Fallback to weak duplicate phrase matching when no explicit target is usable.
  • Balance classes by down-sampling each class to the minimum class count.

Output

Balanced frame with integer binary_label column and equal class counts.

Stage D: Example Objects and Batch Tensors

build_examples + BugReportDataset

Input

Balanced DataFrame with text and vectors.

Transform

  • Create BugExample records from rows.
  • Build vocabulary from training text only.
  • Encode each report to fixed-length input_ids and attention_mask.
  • Broadcast report label into token-level tag_ids for CRF loss.

Output

Train and validation DataLoaders that yield full model input dictionaries.

Stage E: Model Fit, Validation, and Checkpoint Selection

run_training loop

Input

DataLoaders, model hyperparameters, optimizer setup.

Transform

  • Train batches with CRF negative log-likelihood plus optional CRF L2 penalty.
  • Evaluate with class probabilities derived from CRF log-likelihoods.
  • Track best validation F1 and keep matching state dict.
  • Handle KeyboardInterrupt and still save a valid checkpoint.

Output

Saved model file containing best and latest states, vocabulary, config, and metrics.

Feature Branches: What Exactly Happens

The model fuses one text branch with three side-feature branches.

Text Branch

Raw: textual_features.

Processing: lowercase, regex tokenization [a-z0-9_]+, stopword removal.

Output: token IDs and attention mask with fixed max_seq_len.

Temporal Branch

Raw: timestamp text and bug ID values, often via JSON payload.

Processing: parse multi-format datetime, compute days since Unix epoch and gap hours from LUCENE-1.

Output: [days_since_epoch, gap_from_lucene1_hours].

Categorical Branch

Raw: priority/severity/type/component fields or heuristics from text.

Processing: concatenate one-hot vectors for 4 categorical groups.

Output: 29-length vector (5 + 5 + 8 + 11).

Contextual Branch

Raw: assigned_to, fix_version, components (or their text form).

Processing: deterministic first-seen ID mapping with 0 reserved for empty values.

Output: [components_id, assigned_to_id, fix_version_id].

Label semantics in current code are binary. REPORT_LABELS is [non_duplicate, duplicate], so class count C = 2 throughout evaluation and CRF probability scoring.

Tensor Shape Trace Through ADLMBiLSTMCRF

B = batch size, L = max sequence length, E = embedding dim, H = hidden size, C = number of labels (2).

Step Operation Input Output Purpose
1 Embedding lookup [B, L] [B, L, E] Convert token IDs to dense embeddings.
2 LSTM text encoder [B, L, E] [B, L, H] Create contextual token states from text.
3 Concatenate side features [B, 2], [B, 29], [B, 3] [B, 34] Combine non-text channels into a single vector.
4 Side encoder MLP [B, 34] [B, H] Align side feature scale with text hidden width.
5 Broadcast side state [B, H] [B, L, H] Attach report-level side context to each token position.
6 Fusion concat [B, L, H] + [B, L, H] [B, L, 2H] Merge text and side streams.
7 Emission head MLP [B, L, 2H] [B, L, C] Produce token logits for CRF decoding.
8 CRF decode + class scoring emissions + mask decoded tags + [B, C] Get token sequence and report-level class probabilities.

What Each Tensor Means and What Is Inside It

tensor semantics

These tensors are not anonymous numbers. Each index has a specific meaning tied to how the dataset and model are built.

input_ids [B, L] (torch.long)

Token ID per position after vocabulary encoding.

  • 0 is PAD.
  • 1 is UNK for unseen tokens.
  • 2+ are learned vocabulary IDs from training texts.

attention_mask [B, L] (torch.bool)

Marks which token positions are real text versus padding.

  • 1 means valid token.
  • 0 means padding slot.
  • Used by CRF so padding positions do not affect decoding/loss.

temporal_features [B, 2] (torch.float32)

Two date-math values per report.

  • Index 0: days since Unix epoch.
  • Index 1: hours from LUCENE-1 creation time.
  • Fallback [0.0, 0.0] if parsing fails.

categorical_features [B, 29] (torch.float32)

Concatenated one-hot vector over 4 categorical groups.

  • Priority (5), Severity (5), Type (8), Component (11).
  • Usually one active entry per group, often including unknown slots.
  • Represents symbolic metadata as numeric features.

contextual_features [B, 3] (torch.float32)

ID-like context features from deterministic first-seen mapping.

  • Index 0: components_id.
  • Index 1: assigned_to_id.
  • Index 2: fix_version_id.

tag_ids [B, L] and label [B]

Supervision tensors used for training.

  • label is report-level class: 0 non_duplicate or 1 duplicate.
  • tag_ids repeats label over non-padding positions.
  • For class 0 reports, tag_ids are all zeros.

embeddings [B, L, E]

Dense vectors looked up from embedding matrix using input_ids.

  • Each token index maps to an E-dimensional float vector.
  • Embedding values are trainable parameters.
  • Semantically similar tokens can move closer in embedding space.

lstm_output [B, L, H]

Contextual hidden state for each token after the text LSTM.

  • Each vector summarizes token meaning with neighboring context.
  • Still aligned one vector per token position.
  • Feeds directly into fusion with side features.

side_features [B, 34] and side_representation [B, H]

Non-text branch before and after projection MLP.

  • side_features = concat(temporal 2 + categorical 29 + contextual 3).
  • side_encoder MLP transforms [B, 34] into [B, H].
  • This aligns side-channel scale with text hidden size.

fused_representation [B, L, 2H]

Concatenation of token text state and broadcast side state.

  • side_representation is expanded to [B, L, H].
  • Each token gets the same report-level side context.
  • Fusion carries both lexical and metadata signals.

emissions [B, L, C]

Raw per-token class logits produced by emission head MLP.

  • Not probabilities yet.
  • Higher value for a class means stronger score for that token.
  • Consumed by CRF for structured decoding and scoring.

decoded_tags, class_probabilities, loss

Final prediction and optimization objects.

  • decoded_tags: Viterbi best label sequence per report.
  • class_probabilities [B, 2]: normalized report-level class scores.
  • loss: scalar objective = negative CRF log-likelihood (+ optional L2 penalty).

Training and Evaluation Loop

The loop combines batch training with epoch-level validation and best-model selection by F1.

Train One Epoch

train_one_epoch
  • Move each batch to CPU or GPU device.
  • Forward pass includes tag_ids to compute CRF log-likelihood.
  • Loss is negative log-likelihood plus optional CRF regularization term.
  • Run backward pass, gradient clipping, optimizer step.

Evaluate

evaluate + compute_metrics
  • Forward pass in no-grad mode still computes loss and class probabilities.
  • Predictions are argmax over class probabilities from CRF scoring.
  • Metrics: accuracy, macro precision, macro recall, macro F1, Cohen kappa, and average loss.
  • Highest validation F1 controls which checkpoint state becomes best.
Optional Dragonfly mode (--use_dragonfly) searches learning rate, hidden size, dropout, and CRF regularization, then trains the final model with the best candidate.

What Files and Objects Are Produced

Two main artifacts are always important: a prepared dataset CSV and the model checkpoint.

Prepared CSV (prepared_data_out)

  • Balanced binary classes.
  • Cleaned text and materialized vectors.
  • Useful for reproducible reruns without repeating all preprocessing logic.

Checkpoint (.pt)

  • model_state_dict and best_model_state_dict.
  • vocabulary token to ID map.
  • model_config including feature dimensions and label names.
  • best_metrics and run metadata such as status and epoch counters.

How the Pipeline Behaves by Mode

The data front-half is shared, then behavior diverges depending on runtime mode.

  • Runs data loading, schema conversion, vector materialization, label derivation, and balancing.
  • Saves prepared CSV.
  • Stops before building datasets or model weights when --start_training is not set.
  • Includes all preparation steps, then runs split, vocabulary, DataLoaders, and training epochs.
  • Tracks best validation F1 and stores best model state.
  • Saves final checkpoint with complete metadata.
  • If a KeyboardInterrupt occurs, status is set to interrupted.
  • The script still writes a valid checkpoint, using latest available state for model_state_dict.
  • Training progress metadata records last completed epoch.

Glossary of Model Terms

Quick definitions for common terms used across this page and inside the training code.

Embedding Lookup

Operation that maps each integer token ID to a dense trainable vector from an embedding table.

Side Features

Non-text numeric signals concatenated from temporal, categorical, and contextual branches.

MLP

Multi-layer perceptron: stacked linear layers with nonlinear activations used for projection and scoring.

Side Encoder

MLP that projects side features to hidden size H so they can be fused with text hidden states.

Emission Head

Final MLP that converts fused token states into class logits for CRF processing.

Logits

Unnormalized class scores before softmax. Larger logits mean stronger preference for a class.

CRF

Conditional Random Field layer that models label-sequence consistency and scores entire tag paths.

Viterbi Decode

Dynamic-programming algorithm that finds the highest-scoring sequence of labels under the CRF.

Attention Mask

Boolean tensor that marks valid tokens and tells the model to ignore padded positions.

One-Hot Encoding

Vector where one index is 1 and all others are 0, representing a categorical choice.

Broadcasting

Expanding a smaller tensor across a dimension, such as repeating side state across all token positions.

Hidden State

Intermediate learned representation produced by recurrent layers, carrying contextual information.

Log-Likelihood

Score of how probable the observed labels are under model parameters; training maximizes this value.

Regularization

Penalty term added to discourage overfitting; here an optional L2 penalty on CRF parameters.

Gradient Clipping

Caps gradient norm to stabilize training and prevent exploding updates.

Macro F1

Average F1 computed per class and then averaged equally, useful with class imbalance checks.

One Row End-to-End Trace

Concrete example of how one issue report moves across all stages.

Input row (raw CSV)
- Description: "App freezes while opening large project"
- Priority Name: "High"
- Bug Creation Date: "2001-10-09T16:19:16.000+0000"
- Components: "ui"
- Resolution: "DUPLICATE"

After load_modeling_dataframe
- textual_features: normalized cleaned text
- categorical_features: JSON payload (priority and one-hot vector)
- temporal_features: JSON payload (date fields and date math)
- contextual_features: JSON payload (assigned_to/fix_version/components + IDs)

After prepare_training_dataframe
- binary_label: 1 (duplicate)
- dataset_source: source CSV stem
- dataframe may be down-sampled to match minority class count

After BugReportDataset encoding
- input_ids: fixed length integer vector [L]
- attention_mask: [L] where 1 = token and 0 = padding
- temporal_features: [2]
- categorical_features: [29]
- contextual_features: [3]
- tag_ids: [L] with report label broadcast on non-padding tokens

Inside ADLMBiLSTMCRF
- embeddings -> LSTM token states
- side vectors -> side MLP representation
- fused token representation -> emission logits [L, 2]
- CRF decode gives token tags
- class_probabilities gives report-level [non_duplicate, duplicate]

Evaluation output
- predicted class id: argmax(class_probabilities)
- reported metrics include accuracy, macro precision/recall/F1, kappa, and loss
